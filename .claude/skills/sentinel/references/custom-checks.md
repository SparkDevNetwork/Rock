# Sentinel: Team-Specific Checks

Add an entry when we find a real issue worth watching for that doesn't fit a general checklist.
Sentinel reads this file on every review and treats every entry as required. When a pattern
belongs in one of the area checklists, put it there instead (with the commit Id), so the two
copies don't drift apart.

Format:

### YYYY-MM-DD: short title
**Where it applies:** (Obsidian blocks / REST API / etc., or "all")
**What to check:** one or two sentences, concrete enough to act on
**Why:** what actually happened, or what this prevents
