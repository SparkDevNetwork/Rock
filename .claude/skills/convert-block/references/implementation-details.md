# Implementation Details Reference

Execution-specific details for the convert-block skill: type mapping, bag rules, placeholder formats, and a completion checklist.

---

## C# → TypeScript Type Mapping

Used when creating `.d.ts` placeholder files for bags.

| C# type | TypeScript type |
|---|---|
| `string` | `string \| null` |
| `bool` | `boolean \| null` |
| `int` / `long` / `double` | `number \| null` |
| `DateTime?` | `string \| null` |
| `List<T>` | `T[] \| null` |
| `Dictionary<string, string>` | `Record<string, string> \| null` |
| Non-nullable value types | without `\| null` |

---

## Bag Creation Rules

| Bag | When to create |
|---|---|
| `[BlockName]OptionsBag.cs` | Always — even if empty |
| `[BlockName]Bag.cs` | Detail blocks; list blocks with inline modal |
| `[BlockName]RequestBag.cs` | Block action receives structured input |
| `[BlockName]ResponseBag.cs` | Block action returns complex data |

Rules:
- Namespace: `Rock.ViewModels.Blocks.[Category].[BlockName]`
- Every property needs an XML `<summary>` doc comment
- Include the copyright header per `.claude/rules/code-conventions.md` (C# bags use the full block header; `.obs` files use the HTML one-liner)

---

## `.d.ts` Placeholder Instructions

After creating each C# bag, create a matching TypeScript declaration file:

**Location:** `Rock.JavaScript.Obsidian/Framework/ViewModels/Blocks/[Category]/[BlockName]/[bagNameCamelCase].d.ts`

**Format:**
```typescript
// <auto-generated by CodeGenerator />
// This will be replaced by Rock.CodeGeneration — placeholder only.

export type [BagName] = {
    [propertyNameCamelCase]?: [tsType];
    // ... one line per C# property
};
```

These are temporary — they will be overwritten when the user runs Rock.CodeGeneration.

## File-by-File Implementation Checklist

Use this to verify completeness before finishing Phase 4.

### C# Bags (`Rock.ViewModels/Blocks/[Category]/[BlockName]/`)
- [ ] `[BlockName]OptionsBag.cs` created (always required)
- [ ] `[BlockName]Bag.cs` created (if detail or inline modal)
- [ ] Other bags created as needed
- [ ] All properties have `<summary>` doc comments
- [ ] Copyright header present

### `.d.ts` Placeholders (`Rock.JavaScript.Obsidian/Framework/ViewModels/Blocks/[Category]/[BlockName]/`)
- [ ] One `.d.ts` per bag file
- [ ] Type mapping follows the table above

### C# Block (`Rock.Blocks/[Category]/[BlockName].cs`)
- [ ] New GUIDs generated via `scripts/generate-guids.js` for `EntityTypeGuid` and `BlockTypeGuid`
- [ ] Correct base class used
- [ ] Only used nested key classes declared (`AttributeKey`, `NavigationUrlKey`, etc.)
- [ ] All methods have `<summary>` doc comments
- [ ] Copyright header present
- [ ] `IBreadCrumbBlock` implemented (detail blocks, unless clearly not needed)
- [ ] `SecurityGrantToken` implemented (if entity attributes are used)

### Obsidian Component (`Rock.JavaScript.Obsidian.Blocks/src/[Category]/[blockName].obs`)
- [ ] `onConfigurationValuesChanged(useReloadBlock())` included
- [ ] Correct template used (DetailBlock, Block, or custom)

### Partials (`Rock.JavaScript.Obsidian.Blocks/src/[Category]/[BlockName]/`)
- [ ] `viewPanel.partial.obs` — uses `ValueDetailList` (detail blocks)
- [ ] `editPanel.partial.obs` — uses `ContentSectionContainer`, `propertyRef`, `ValidPropertiesBox` (detail blocks)
- [ ] `types.partial.ts` — created if navigation URLs or shared types exist
- [ ] `gridSettingsModal.partial.obs` — created if server-side filters are used (list blocks)

### WebForms Chopped
- [ ] `RockWeb/Blocks/[Category]/[BlockName].ascx` deleted
- [ ] `RockWeb/Blocks/[Category]/[BlockName].ascx.cs` deleted
